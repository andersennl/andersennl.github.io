Corlys · Webhooks

What your server receives

Corlys sends journal entries to webhook addresses you set up yourself. This page describes the requests, so you can build a receiver in whatever language or tool you like.

Endpoints

You can add as many endpoints as you need. Each one has an address, an optional token, a content type and a way of sending:

  • Content: the entry as text, or each recording as an audio file. Text is the default, for typed and dictated entries alike. Audio is meant for receivers that want to transcribe themselves.
  • Sending: automatically, or only when you tap send in the entry.

Every request is a POST to the address you entered. Photos and locations are not sent. Entries imported from Day One are not sent automatically.

Text endpoints

A text endpoint receives one request per new entry, when you close the editor and the entry has its title. However many dictations went into the entry, it arrives once, as a whole. The body is JSON (Content-Type: application/json):

{
  "id": "5B0C7C0E-6B1F-4F0B-9C55-2F3E7A0D9A11",
  "title": "Walk by the harbour",
  "text": "Cold coffee, **great** light.\n\n- Boats\n- Wind",
  "createdAt": "2026-10-11T07:42:10Z"
}
FieldContent
idUUID of the entry. Stays the same when you send an entry again, so you can replace instead of duplicate.
titleThe short title the app gave the entry.
textThe entry in your own words, typed or dictated. Formatted entries arrive as Markdown; underline arrives as <u>.
createdAtDate and time of the entry in ISO 8601, in UTC. You can change it in the app.

The app transcribes on the device, so a text endpoint needs no audio and no speech service.

Audio endpoints

An audio endpoint receives one request per dictation as multipart/form-data. If an entry has three dictations, three requests arrive, one after another in the order they were recorded, when you close the editor. A recording is sent even if its transcription failed.

FieldContent
createdAtDate and time the recording started, in ISO 8601, in UTC.
durationLength of the recording in seconds, with one decimal.
languageLanguage of the dictation as set in the app, for example de or da_DK.
dataThe recording as a file, normally M4A (audio/mp4).

The file is named after the time the recording started, in UTC to the millisecond: YYYY-MM-DD_HH-MM-SS-mmmZ, for example 2026-10-19_07-42-10-482Z.m4a. Sorted by name, the recordings of an entry are in the order they were spoken, and no two share a name. The name contains no colons, slashes or spaces, so you can save it as it is on Windows, macOS and Linux.

A request looks like this (the boundary changes with every request):

POST /your/path HTTP/1.1
Authorization: Bearer <token>
Content-Type: multipart/form-data; boundary=AudioToStructure-…

--AudioToStructure-…
Content-Disposition: form-data; name="createdAt"

2026-10-19T07:42:10Z
--AudioToStructure-…
Content-Disposition: form-data; name="duration"

48.3
--AudioToStructure-…
Content-Disposition: form-data; name="language"

da_DK
--AudioToStructure-…
Content-Disposition: form-data; name="data"; filename="2026-10-19_07-42-10-482Z.m4a"
Content-Type: audio/mp4

<binary audio>
--AudioToStructure-…--

A dictation lasts up to ten minutes. The app waits up to 120 seconds for an audio request and up to 30 seconds for a text request.

Token and response

  • If you set a token for an endpoint, it arrives as Authorization: Bearer <token>. Without a token there is no Authorization header. The token is stored in the keychain of your device.
  • Any 2xx response counts as sent. For other codes the app shows the message field of a JSON response, for example {"message": "text is empty"}.
  • The app does not retry on its own. The result of the last attempt is shown in the entry, where you can send again.

Reaching your server

The app sends to https:// addresses. Plain http:// is accepted only for Tailscale addresses (100.64.0.0/10), so a home server without a certificate works through Tailscale.
